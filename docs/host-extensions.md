# E：宿主扩展能力

- 设计接受日期：2026-10-08。
- 当前成熟度：`prototype`；E01a 固定 T1 工程范围已完成并通过 clean Windows CI。
- 范围：SDK 扩展契约、资源格式与独立验证面；真实宿主接入分项验收。
- 相关证据：[E01a 验收记录](./validation/e01-contributions.md)。

这条平行线让插件通过稳定接口贡献外观、文字、设置和业务能力。
新增同类业务功能应通常只需增加插件；新增原生权限或底层能力仍由 Host
提供受控 adapter。接口可扩展不表示任意代码已经获准运行。

## E01a：贡献目录基础

公开入口为不依赖 React 的 `@flowtools/sdk/extensions`。它提供严格的
formatVersion 1 文档解析、Host 创建的内存目录和 PluginRegistry 生命周期投影。
Host 从 PluginRegistry 绑定插件 ID/版本，使用目录的
`createOwner(pluginId, version): ExtensionContributionOwner` 取得
`{ pluginId, version, generation }`。这里的 generation 是
目录发放的本地 owner epoch，独立于卸载重装可能归零的插件 loaded generation；
它不是可跨 IPC 使用的认证凭据、包签名或用户 grant。

文档形状如下；`value` 目前只是有界 JSON，主题、语言和设置的业务 Schema
分别由 E02/E03/E04 定义。示例内容不代表已实现 CSS 应用或翻译解析。

```json
{
  "formatVersion": 1,
  "contributions": [
    {
      "id": "sample-theme",
      "kind": "theme",
      "value": { "name": "Sample" }
    }
  ]
}
```

- `parseExtensionContributions(unknown)` 严格校验文档，复制并冻结被接受的数据。
  未知字段、未知类型、重复 ID、非 JSON 值和超预算数据必须拒绝。
- `ExtensionContributionRegistry.createOwner(pluginId, version)` 由可信 Host
  调用，为当前插件实例取得目录发放的 owner；在同一目录实例内，重装与重建
  投影不复用旧 epoch。目录重新创建后不保留任何历史状态。
- `ExtensionContributionRegistry.replace(owner, document)` 原子替换同一 owner
  的贡献；失败保留之前的有效目录。返回的清理函数只清理其对应的一次替换，
  旧清理函数不能撤下后来替换的内容。
- `revoke(owner): boolean` 只撤下匹配 owner 的当前内容；过期代际不能撤下新实例。
- `getSnapshot()` 返回按插件 ID/kind/贡献 ID 排序的只读数组，在语义内容无变化
  时保持引用稳定；对象键顺序和贡献顺序不改变结果。`subscribe()` 提供变更通知；
  消费者不得修改快照或嵌套 JSON。
- `projectPluginContributions(plugins, contributions, readDocument)` 返回投影
  的清理函数，只为 enabled 且依赖满足的当前插件投影内容。`readDocument` 是可信 Host
  选择文档的同步 callback，不是插件文件扫描器或任意路径读取接口。
  停用、卸载、依赖不满足和投影销毁都撤下对应内容，迟到旧 owner 被拒绝。
  文档读取或通知期间重入停用/卸载，也不能重新发布已经失效的贡献。

文档和单项 contribution envelope 严格拒绝未知字段，例如额外的 `pluginId`。
`value` 仍是普通不透明 JSON，可包含名为 `pluginId`、`permissions` 等业务键；
Host 不从这些内容派生 owner、grant 或操作授权。没有递归身份键黑名单，
数据也不能通过这些键改变目录归属或自行授权。

解析复用的 JSON 校验还须拒绝继承 `toJSON` 的数组子类、稀疏数组或非索引
属性等可执行/有损输入；合法 JSON 和现有 Manifest 文档格式保持不变。
字节预算在序列化整个输入前增量计算并超限即停；固定 prototype 上限见
公开的 `extensionContributionLimits`，不把这些软预算称作 OS 资源隔离。

E01a 不修改现有 Manifest v1，不增加插件文件加载、动态执行、网络、原生命令、
持久化、CSS 注入或设置写入入口。SDK 的 Host 管理 API 不是授予插件的 capability。
未来从已安装包读取资源必须先通过 G5 的包身份和准入，再连接同一目录。

## 第一批：主题、语言与设置

第一批按 E01a → E02 → E03a/b/c → E04 推进，逐项独立提交；E10 的版本、
错误和清理规则贯穿各子项。先使用独立验证面，避免直接重写 G7 页面。

主题使用 FlowTools 语义 tokens，再由内部映射至 HeroUI。目标覆盖颜色、
面板/控件圆角、边框、字体、阴影与动画偏好；布局密度和控件尺寸设合理范围。
解析优先级为内置默认 → 用户选中主题 → 用户覆盖。固定圆角等硬编码需要在
实际页面接入时单独处理，不能仅凭变量变更宣称全界面支持主题。
任意 CSS、远程字体/资源、DOM 修改和布局树替换不属于首期主题契约。

E03 分三项验收：

- E03a：随应用提供默认启用的内置最小 i18n 插件，离线贡献 Host 简中/英文，
  覆盖启动器、设置、插件管理、错误与恢复入口。Host 保留最小文本接口和
  可信回退文字，插件损坏时仍能恢复；更多语言和高级翻译功能按需安装。
- E03b：SDK 提供统一文本 ID、参数和语言变化接口，覆盖插件面板、命令名称、
  设置名称、提示与无障碍标签；机器 command ID 和错误码保持稳定。
- E03c：第三方语言包按目标插件身份、资源版本和语言提供翻译；缺词条与
  参数不匹配回退。插件启用不自动覆盖其他插件文字，需明确选择与解析规则。

机器翻译、术语库、翻译编辑器、完整 RTL 与多语言排版另立子项。
不通过遍历 Host DOM 或替换任意原文来实现第三方翻译；隔离插件通过受控接口
取得自己的语言资源。权限含义、身份和恢复说明的可信呈现仍由 Host 管理。

E04 使用声明式设置 Schema，统一默认值、校验、重置和变化通知；复杂设置
面板作为后续受控视图。普通偏好与敏感凭据引用分开，迁移与持久化复用既有
Runtime 数据体系。E01a 的 `settings` JSON 不是已经完成的设置 Schema。

第一批验收样例：用户切换主题和中英语言；开发者增加第三套主题、第三种语言
及设置分组，已有宿主页面无需新增对应业务分支；停用与失败回退均能验证。

## 第二批与第三批

第二批交付 E05/E06/E08。Provider 规则逐类定义：主题选一个，翻译按语言与
命名空间解析，搜索合并去重，预览按资源类型匹配，导入导出由用户选择格式。
优先用翻译验证业务协议，服务传输、依赖与版本锁复用 G4。

第三批交付 E07/E09 与完整 E10。资源交接复用 Host 发放的句柄和授权，明确
期限、释放、大内容传输及可继续处理的动作。验收链先使用真实轻量内置插件：
选中文字 → 翻译 → 继续处理 → 字数统计或导出。OCR、模型调用与完整工作流
编辑器保留为后续插件，不在协议基础里顺带实现。

布局先开放受控参数，再开放明确插槽；每个插槽都规定焦点、响应式、导航、
错误和停用恢复。第三方面板仍使用 G5 的隔离域，不进入 Host 主 React 树。

## 每个扩展点的共同要求

必须定义 Host 绑定身份、版本、适用范围、用户选择、多实现共存、失败回退、
取消、资源预算和撤销清理。声明可用、实现支持、用户授权分别表示不同事实。
不得由主题、语言资源或 enabled 元数据授予文件、网络、数据和工具权限。

纯数据贡献无需常驻执行；业务服务使用受控调用。贡献必须有命名空间，恶意
或不兼容内容不得污染其他 owner；持久恢复和升级沿用 Runtime/package gate。
T1 共享 realm 的代码仍可绕过 JavaScript 接口，目录校验不构成安全沙箱。

相关风险 SEC-002/003/007/010 保持 open；
[ADR-0001](./adr/0001-plugin-trust-boundaries.md) 的信任等级不变。
工程回归、实际界面验收、独立安全审阅与 production 批准分别记录。
